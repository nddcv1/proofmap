# ProofMap v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a rule-based, evidence-backed prerequisite graph from math-kb chunks and render it as a single-file offline HTML.

**Architecture:** Python package with adapter → node extraction → proof attribution → rule edge extraction → corrections → graph/audit → HTML renderer. JSONL/JSON contracts between stages.

**Tech Stack:** Python 3.10+, PyYAML, pytest, Cytoscape.js + dagre (vendored).

**Spec:** `docs/superpowers/specs/2026-11-01-proofmap-design.md`

## Global Constraints

- v0.1 has no runtime LLM calls; LLM is v0.2.
- Every automatically generated edge must carry a verbatim evidence quote plus char offsets.
- Canonical node IDs must never be derived from the OCR label alone.
- The HTML must be a single offline file with vendored JS and no CDN requests.
- Do not commit textbook OCR, private notes, raw PDFs, build outputs, or caches.
- Output must be deterministic: stable ordering, no wall-clock timestamps in `graph.json`.
- All file I/O is UTF-8.
- Python style: stdlib dataclasses, type hints, small modules, no runtime deps beyond PyYAML.

```python
def write_jsonl(path: Path, items) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open("w", encoding="utf-8", newline="\n") as fh:
        for item in items:
            fh.write(canonical_json(item.to_dict()) + "\n")

def read_jsonl(path: Path, cls):
    with path.open("r", encoding="utf-8") as fh:
        return [cls.from_dict(json.loads(line)) for line in fh if line.strip()]

def canonical_json(obj) -> str:
    return json.dumps(obj, ensure_ascii=False, sort_keys=True)
```

- [ ] **Step 3: Implement adapter and extraction**

`load_chunks` reads JSONL and validates required keys.

Extraction rules:

- Only `kind in {"definition", "theorem"}` become nodes.
- Prefix regex: `^(定义|定理|引理|推论|命题)\s*([0-9]+(?:\.[0-9]+)*)?`.
- Parenthetical title regex: `^[^(（]*[（(]([^）)]{1,40})[）)]`.
- Title fallback: text after prefix up to first `。`/`；`/`;`, max 40 chars.
- `subkind` from prefix: 定义→definition, 定理→theorem, 引理→lemma, 推论→corollary, 命题→proposition.
- Canonical ID: if numeric label exists and is unique within the book, use `f"{book_id}:{prefix}{number}"`. Otherwise use `f"{book_id}:{section_key}:{ordinal}"`, where `section_key` is a slug of section/chapter (allow Chinese and alphanumerics) and ordinal is a per-section counter.
- Aliases include `f"{prefix} {number}"` and `f"{prefix}{number}"`, the parenthetical title, and the section/subsection if it contains 定理/引理/推论/命题/公式/不等式.
- Duplicate numeric labels in a book must receive fallback IDs and append an audit message.
- Preserve `source_chunks=[chunk_id]`.
- `statement=text`, `proof=""`.

- [ ] **Step 3: Implement attribution**

Algorithm:

1. Iterate chunks in order; only `kind == "proof"`.
2. Look back up to 5 chunks, same book. Candidate kinds `theorem`, `example`, `exercise`.
3. Score:
   - same non-empty section: +0.45;
   - if either section is empty and chapters match: +0.25 and mark degraded;
   - distance 1/2/3/4/5: +0.40/0.30/0.22/0.15/0.10;
   - proof text mentions candidate label (spaces removed) or title (length >= 3): +0.30;
   - candidate text contains `证明`: -0.50.
   - clamp to `[0, 1]`.
4. Attach if top score >= 0.55 and margin >= 0.15; if degraded, force `ambiguous`.
5. Target ID:
   - theorem/definition candidate: use the extracted node ID; for example/exercise (not nodes), use `f"{book_id}:{kind}:{chunk_id}"`.
6. `non_graph = target_kind in {"example", "exercise"}`.
7. `apply_attachments` appends a proof chunk's text to the matching node's `proof`, separated by `\n\n`.
8. `detached` attachments never merge proofs.

- [ ] **Step 3: Implement resolution and L1–L3**

`NodeIndex`:

- index `(book_id, normalized_label)` → IDs.
- normalized label removes whitespace only.
- dotted number: filter book-wide.
- single-level: filter `chapter == current_chapter`; if no chapter, return all and let the caller treat as ambiguous.
- alias index maps alias → IDs; generic aliases are filtered later.
- `preceding` uses insertion order per `(book, chapter)`.

`make_evidence`:

```python
def make_evidence(text: str, start: int, end: int, context: int = 40) -> Evidence:
    lo = max(0, start - context)
    hi = min(len(text), end + context)
    return Evidence(quote=text[lo:hi], char_start=lo, char_end=hi)
```

L1 numbered:

- Regex `(?P<kind>定理|引理|推论|命题|定义)\s*(?P<num>\d+(?:\.\d+)*)`.
- Resolve; exactly one target → edge; zero → issue `unresolved_ref`; multiple → issue `ambiguous_ref` and no edge unless `include_ambiguous`, then tentative edge to first target with a note.
- Edge type `numbered_ref`, confidence `explicit`, source `rule`.

L2 named:

- Build alias list from node aliases/titles, length >= 4 Chinese chars or contains Latin letters.
- Generic blacklist: `中值定理`, `基本定理`, `定理`, `公式`, `不等式`, `微分中值定理`.
- Longest-first, non-overlapping matches. Resolve by alias; exactly one → `named_ref` explicit edge; multiple → issue.
- Skip if the matched alias spans the target's own label at position 0.

L3 anaphora:

- Patterns: `上述定理`, `前一定理`, `上节定理`, `由上述`, `上述结论`.
- Resolve to `preceding` node; if found → `anaphora_ref`, confidence `tentative`; else issue.
- Anaphora edges are always generated; HTML hides them by default.

`build_all` order:

2. extract nodes + audit;
3. load corrections; apply aliases;
4. attach proofs; apply force/detach;
5. extract L1–L4 edges for attached non-graph=false targets;

CLI details:

- argparse subcommands.

- Exit codes: 0 success, 1 input error, 2 blocking audit issue, 3 eval gate failed.
